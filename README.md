# Description

*Active subspaces* are part of a set of tools for subspace-based dimension reduction in complex simulation models in science and engineering. This repository contains data sets and associated [Jupyter](http://jupyter.org) notebooks that apply active subspace methods to a wide range of science and engineering models. The Python implementations of the methods are available on [Github](http://github.com/paulcon/active_subspaces/). More information on active subspaces can be found at [activesubspaces.org](http://activesubspaces.org).

Each data set's directory contains a Jupyter notebook (`.ipynb`), the data or model it analyzes, and a `DATA.md` that describes the files, their provenance and license, and what is unknown about them. Data files are mostly text (`.txt`, `.csv`) or NumPy `.npz`. Github renders the notebooks when you click an `.ipynb` file, but its rendering of mathematical expressions is not as robust as [nbviewer.org](https://nbviewer.org/). To view a notebook there, paste its Github link into the box at [nbviewer.org](https://nbviewer.org/). Each notebook also has links to associated publications for more details.

# Data sets

The data sets are grouped by application area, one directory per category. Each data set is one of two kinds, marked at the end of its entry (MHD_Generator has one part of each):

* **Stored data:** an outside simulation code (CFD, hydrology, battery, wind turbine, solar cell, cardiac cell, circuit simulator, …) generated the data. The files in the directory are the record of those runs. Most cannot be regenerated from this repository. Where the data were made for this repository with an outside code (SMRT, Cantera, SIPNET, ngspice, L2-Sea, XFOIL, Myokit, PyCO2SYS, PROCESS, PyBaMM and PyBOP, pyloric, Raven, HallThruster.jl, fdfault, OpenAeroStruct, OpenDSS, FaIR, virsim, MODFLOW-2005, pyrcel, Hector and Matilda, the Minnesota COVID-19 model in R, the pulmonary pulse-wave solver, and the CO₂ benchmark's executable), `generate_data.py` can regenerate them where that code is installed, and otherwise exits with a message saying what to install.
* **Python model:** the model that generates the data is Python code in the directory (a `*_model.py` module, or a closed-form formula in the notebook). The notebook can call it as needed, and a `generate_data.py` script regenerates any shipped data files.
